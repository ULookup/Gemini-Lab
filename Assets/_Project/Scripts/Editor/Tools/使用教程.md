# Gemini-Lab 七件套开发工具使用教程

本文档将手把手教你使用七个开发工具，每一步都会详细说明。

**阅读顺序**：如果你只想快速知道"哪个工具能解决我当前的问题"，直接跳到 [第 8 节](#8-用工具解决项目问题清单逐一对照)。

---

## 0. 准备工作：打开工具菜单

所有工具都挂在 Unity 顶部菜单栏的 **Tools → Gemini-Lab** 下。

在 Unity 编辑器中，点击顶部菜单栏的 **Tools**，展开后找到 **Gemini-Lab** 子菜单，七个工具都在里面。每个工具打开后会变成一个独立的浮动窗口，你可以把它拖到任意位置停靠。

```
Tools → Gemini-Lab → ├─ Debug Display Manager
                       ├─ Furniture Label Validator
                       ├─ UI Panel Diagnostic
                       ├─ Tarot System Inspector
                       ├─ Asset Reference Scanner
                       ├─ Furniture Interaction Preview  (不在菜单里，见下文)
                       └─ Pet Patrol Path              (不在菜单里，见下文)
```

后面两个工具（Furniture Interaction Preview 和 Pet Patrol Path）不是独立窗口，而是改写了 Inspector 面板的行为，使用方式不同，后面会详细说明。

## 1. Debug Display Manager（调试显示管理器）

### 它是干什么的

你的项目里有大量调试用的界面元素和日志输出——聊天预览气泡、塔罗牌预览、占位 GameObject、冗余 Debug.Log。这些东西在开发时很有用，但会干扰你排查其他问题，也可能影响性能。

Debug Display Manager 就是一个**总开关**。你可以一键关掉所有调试内容，也可以分门别类地控制。

底层原理：它创建了一个 `DebugDisplaySettingsSO` ScriptableObject 存放在 `Assets/_Project/Resources/` 下，运行时代码通过 `DebugDisplaySettingsSO.Instance` 读取开关状态。已经有四个运行时代码被接入了这套开关：

- `ChatMessageListView.cs` — 聊天预览
- `ReadingBubble.cs` — 塔罗牌解读气泡
- `TarotSummaryPreview.cs` — 塔罗摘要预览
- `PetRuntimeBootstrap.cs` — 占位宠物对象

### 打开方式

点击菜单 **Tools → Gemini-Lab → Debug Display Manager**。

一个名为 "Debug Display" 的窗口会弹出。

### 界面说明

窗口从上到下分为三个区域：

**区域一：主开关（Master Toggle）**

最上方是一个勾选框 **Enable Debug Display**。这是总闸，关掉它之后，下面四个分类开关全部失效。当你正在排查一个正式功能的 bug，不想被调试内容干扰时，直接关掉它即可。

**区域二：分类开关（Categories）**

一个可折叠的区域，点一下 **Categories** 左边的三角展开。里面有四个子开关：

| 开关名 | 控制什么 |
|--------|----------|
| Chat Preview | PhoneChat 界面里的聊天消息预览气泡 |
| Tarot Preview | 塔罗牌阅读气泡和摘要预览 |
| Placeholder Objects | 运行时的占位 GameObject（如占位宠物） |
| Verbose Logging | 各个子系统的详细日志输出 |

这四个开关只有在主开关打开的情况下才生效。这是设计好的——主开关一旦关闭，分类开关的值虽然还保留，但实际不起作用。

**区域三：快捷操作和状态摘要**

- 两个大按钮 **Enable All** / **Disable All**：一键打开或关闭所有开关（包括主开关）。
- **Status Summary**：列出每一个开关当前的 ON/OFF 状态，用绿色（ON）和红色（OFF）标注，一目了然。

### 使用场景举例

**场景 1：你要排查家具交互的 bug，但满屏都是聊天预览气泡，很烦。**

1. 打开 Debug Display Manager
2. 取消勾选 **Chat Preview**
3. 气泡全部消失，你现在可以专心看家具了
4. bug 修完后，点 **Enable All** 恢复

**场景 2：你怀疑某个调试日志在刷屏，影响性能。**

1. 打开 Debug Display Manager
2. 取消勾选 **Verbose Logging**
3. Console 清净了
4. 但如果总开关也关了，会关掉所有调试内容——确认你只想关日志的话，只需要动 **Verbose Logging** 一个开关

### 注意事项

- 修改开关后，不要手动去移动或删除 `Assets/_Project/Resources/DebugDisplaySettings.asset` 文件，否则窗口打开时会重新创建一份，之前设置的开关状态就丢失了。
- 运行时代码通过 `Resources.Load` 读取这个 asset，所以这个文件必须存在于 `Resources` 目录下。工具首次打开时会自动创建，不需要你手动操作。

## 2. Furniture Label Validator（家具标签验证器）

### 它是干什么的

你的 Apartment 场景里有大量家具 GameObject。每个家具需要：
- 挂 `SceneFurnitureDefinitionHint` 组件（标注它是哪件家具、什么类别、什么交互类型）
- 被注册到场景中的 `ApartmentSceneFurnitureBindings` 里（不然系统不知道它的存在）
- 有一个 `SpriteRenderer` 并且 Sprite 不为空（否则看不见）
- DefinitionId 不能为空（否则对不上配置表）

这个工具一次性扫描整个 Apartment 场景，把每件家具的完成情况列出来，有问题的标红/标黄，点击名字就能定位到 GameObject。

### 打开方式

点击菜单 **Tools → Gemini-Lab → Furniture Label Validator**。

### 界面说明

**第一行：场景路径 + Scan 按钮**

默认填好了 `Assets/_Project/Scenes/Apartment/Apartment_Main.unity`。如果你的场景路径不同，可以修改。

点击 **Scan** 按钮开始扫描。扫描过程是即时的，结果立刻显示。

**第二行：Show only issues 勾选框**

勾选后只显示有问题（Warning 或 Error）的条目，正常的不显示。不想被大量绿色 OK 行淹没时用这个。

**第三行：统计摘要**

一行彩色数字：
- Total：扫描到的家具总数
- OK（绿色）：一切正常的数量
- Warnings（黄色）：有小问题但不影响运行的数量
- Errors（红色）：有严重问题的数量

**表格列说明**

| 列名 | 含义 |
|------|------|
| Object | GameObject 名称，点击可定位到 Hierarchy |
| Hint | 是否有 SceneFurnitureDefinitionHint 组件 |
| Binding | 是否在 ApartmentSceneFurnitureBindings 中注册 |
| Furniture | 是否挂了 Furniture 组件 |
| DefId / Label | 详细信息：正常时显示类别和交互类型，有问题是显示具体问题 |

**颜色含义**

- 红色行背景：Error — 缺 Sprite、DefinitionId 为空这类严重问题
- 黄色行背景：Warning — Category 设为 Unknown、未注册 Binding 等
- 无色背景：OK — 一切正常

### 使用场景举例

**场景 1：新加了一件家具，想知道是否漏了什么步骤。**

1. 在 Apartment 场景中摆好家具
2. 打开 Furniture Label Validator
3. 点 **Scan**
4. 在列表中找到你新加的家具（名称按字母排序，Error 排最前面）
5. 如果显示 Error/Warning，看 **DefId / Label** 列写的问题描述，回到 Inspector 修复

**场景 2：合并了别人的分支后，想快速检查场景是否完整。**

1. 打开 Apartment 场景
2. 打开 Furniture Label Validator
3. 点 **Scan**
4. 看统计栏：Errors 如果是 0，Warnings 只有几个已知的无害项，就可以放心了

### 注意事项

- 如果 Apartment 场景还没打开，工具会自动以 Additive 模式打开它。不过最好自己先打开，避免多个场景叠加造成的混乱。
- `HasBinding` 为 No 不一定就是 bug——有些场景装饰物确实不需要绑定到交互系统。这些会被标为 Warning（"OK (unbound scene decor?)"），你可以自行判断。

## 3. UI Panel Diagnostic（UI 面板诊断器）

### 它是干什么的

你的 UI 系统（`IUIPanel`）管理着很多面板。这个工具扫描当前活跃场景中所有 Canvas 对象，检查每个面板的组件是否完整、是否正确注册到 UI 系统。

检查项包括：
- 是否实现了 `IUIPanel` 接口（否则不会被 UIManager 管理）
- Canvas 是否 enabled
- 有没有 GraphicRaycaster（否则点不动）
- TMP 文本的字体是否缺失
- Image 组件的 Sprite 是否缺失

### 打开方式

点击菜单 **Tools → Gemini-Lab → UI Panel Diagnostic**。

### 界面说明

**第一行：说明文字 + Scan Scene 按钮**

先打开你要检查的场景，然后点 **Scan Scene**。

**第二行：Show only panels with issues 勾选框**

勾选后只显示有问题的面板。

**第三行：统计摘要**

- Total Panels：扫描到的面板总数
- Healthy（绿色）：一切正常的面板数
- Issues（黄色）：有问题的面板数

**表格列说明**

| 列名 | 含义 |
|------|------|
| Panel Name | 面板名称，点击可定位 |
| Canvas | 是否有 Canvas 组件 |
| PanelId | IUIPanel 注册的 Id（显示为数字），未注册则显示 "Not Registered" |
| Active | 该 GameObject 在 Hierarchy 中是否激活 |
| Issues | 具体问题列表 |

### 使用场景举例

**场景 1：某个面板在游戏里看不到，或者点了没反应。**

1. 运行游戏（或直接在 Editor 中检查该场景）
2. 打开 UI Panel Diagnostic，点 **Scan Scene**
3. 在列表中找到那个面板
4. 看 Issues 列写了什么：
   - "Canvas disabled" → Canvas 组件没勾选 enabled
   - "No GraphicRaycaster" → 加一个 GraphicRaycaster 组件
   - "No IUIPanel implementation" → 脚本没实现 IUIPanel 接口
   - "TMP 'xxx' has no font" → 某个 TMP 文本组件没指定字体
   - "Image 'xxx' has no sprite" → 某个 Image 组件没指定图片

**场景 2：新增了一个 UI 面板，想确认配置是否齐全。**

1. 在场景中选中你的新面板
2. 打开 UI Panel Diagnostic，点 **Scan Scene**
3. 确认你的面板在列表中，且 Issues 显示 "OK"

### 注意事项

- 这个工具扫描的是**当前活跃场景**（`SceneManager.GetActiveScene()`）。如果你同时打开了多个场景，确保你要检查的场景是 Active 的那个。
- 当前扫描的是顶层 Canvas 和带有 IUIPanel 的 GameObject。如果一个面板是另一个 Canvas 的子对象，它可能不会被单独列出——这是正常的，因为子面板通常共享父 Canvas 的配置。

## 4. Tarot System Inspector（塔罗系统检查器）

### 它是干什么的

塔罗系统是你项目中比较复杂的模块，涉及：
- `ITarotService` — 塔罗服务接口（发牌、解读）
- `ITarotSessionRecordStore` — 会话记录存储（每次占卜的历史）
- `TarotDeckSO` — 卡牌牌组
- `TarotCardSO` — 单张卡牌数据
- `TarotSessionRecord` — 一次占卜的完整记录（三张牌+解读+运势）

在 Editor 模式下你看不到运行时的状态。Tarot System Inspector 让你在 Play Mode 中实时查看塔罗系统的内部状态：服务是否注册、牌组有哪些卡牌、有哪些历史占卜记录，还可以删除不想要的记录。

### 打开方式

点击菜单 **Tools → Gemini-Lab → Tarot System Inspector**。

### 前提条件

这个工具**只有在 Play Mode 中才能看到数据**。如果你还没点 Play，窗口里会显示 "Enter Play Mode to inspect."

### 界面说明

**第一行：标题 + Refresh 按钮**

显示 "Tarot System Status"，旁边有一个 **Refresh** 按钮。进入 Play Mode 后点一下 Refresh 获取最新状态。

**第二行：服务状态**

一个灰底方框，里面三行：
- `ITarotService: Registered / MISSING` — 塔罗服务是否注册到 ServiceLocator
- `ITarotSessionRecordStore: Registered / MISSING` — 记录存储是否注册
- `Deck: 牌组名 (N cards)` — 当前载入的牌组和卡牌数量

如果任一项显示 MISSING，说明对应的服务没有注册到 ServiceLocator，你需要检查 DI 容器的初始化流程。

**第三行：Session Records（会话记录）**

可折叠区域，标题显示记录总数。

展开后：
- 一个 **Filter** 输入框：输入关键词（SessionId、问题文本、日期）可以过滤记录
- 一个 **Delete All** 按钮：删除全部记录（会有确认对话框）
- 下方是一个可滚动的列表，每条记录显示：
  - SessionId 和日期
  - 红色 **Delete** 按钮（删除这一条）
  - 用户提出的问题（Q: xxx）
  - 三列（Past / Present / Future）：
    - 卡牌 ID 和正逆位（Upright / Reversed）
    - Angel 解读片段
    - Devil 解读片段
  - 运势信息：Fortune Level（1-5）、Lucky Color、Lucky Number、Lucky Time、Lucky Action

**第四行：Deck Cards（牌组卡牌）**

可折叠区域，标题显示卡牌总数。

展开后列出当前牌组中所有卡牌：
- 卡牌 Id
- 中文名（DisplayNameZh）
- 英文名（DisplayNameEn）
- 正位关键词
- **Ping** 按钮：点击后在 Project 窗口中高亮定位到该 `TarotCardSO` asset

### 使用场景举例

**场景 1：测试塔罗占卜功能，想看看记录有没有正确保存。**

1. 进入 Play Mode
2. 进行一次塔罗占卜
3. 打开 Tarot System Inspector，点 **Refresh**
4. 在 Session Records 列表中应该能看到刚才的占卜记录
5. 展开记录，检查三张牌的 ID 和解读文本是否正确

**场景 2：测试过程中产生了大量垃圾记录，想清空重来。**

1. 在 Play Mode 中打开 Tarot System Inspector
2. 点 **Delete All**
3. 确认对话框点 **Delete All**
4. 点 **Refresh** 确认记录已清空

**场景 3：想确认某张卡牌的配置是否正确。**

1. 进入 Play Mode（不需要运行游戏逻辑，只要在 Play Mode）
2. 打开 Tarot System Inspector
3. 展开 **Deck Cards** 区域
4. 浏览卡牌列表，找到你要检查的卡牌
5. 点 **Ping** 定位到该 asset，在 Inspector 中查看详细配置

### 注意事项

- 退出 Play Mode 后，和运行相关的数据（服务注册、会话记录）会清空，这是正常的。
- 删除记录的操作直接影响 `ITarotSessionRecordStore`，不可恢复。
- 如果点 Refresh 后 Deck Cards 区域是空的，说明 `ITarotService` 没有注册或 Deck 没有正确载入。

## 5. Asset Reference Scanner（资源引用扫描器）

### 它是干什么的

Unity 项目中最常见的一类 bug 就是"引用丢失"——某个 ScriptableObject 里的 Sprite 字段变空了，某个 Prefab 上的组件引用丢失了，某个脚本（MonoScript）找不到了。这些问题在运行时才会暴露，很难在 Editor 中提前发现。

Asset Reference Scanner 会遍历 `Assets/_Project/` 下所有 ScriptableObject 和 Prefab，逐一检查它们序列化字段中的引用是否完整。发现丢失的引用就列出来，点击即可定位。

### 打开方式

点击菜单 **Tools → Gemini-Lab → Asset Reference Scanner**。

### 界面说明

**第一行：两个扫描按钮 + 状态文字**

- **Scan All SO & Prefab**：扫描 `Assets/_Project/` 下所有 ScriptableObject 和 Prefab。这个操作可能需要几秒到十几秒，取决于项目大小。
- **Scan Selected**：只扫描你在 Project 窗口中当前选中的资源。适合快速检查某一个或几个资源。
- 右侧灰色文字显示当前状态（"Ready." / "Scanning..." / "Done. Scanned X assets, Y with issues."）。

**第二行：Show only assets with broken references**

勾选后只显示有问题的资源，健康的隐藏。

**第三行：统计摘要**

- Scanned：扫描了多少资源
- Broken（红色）：有多少资源有丢失引用
- Healthy（绿色）：有多少资源完全正常

**表格列说明**

| 列名 | 含义 |
|------|------|
| Asset | 资源路径，点击可在 Project 中定位 |
| Type | 资源类型：SO（ScriptableObject）或 Prefab |
| Issues | 具体问题，如 "Missing ref: Sprite (PPtr<Sprite>)" |

### 使用场景举例

**场景 1：合并分支后做一次全面体检。**

1. 打开 Asset Reference Scanner
2. 点 **Scan All SO & Prefab**
3. 等待扫描完成
4. 如果 Broken > 0，在列表中逐个点击有问题的资源
5. 根据 Issues 列的描述修复引用
6. 再次点 Scan 确认所有问题已修复

**场景 2：改了一个 ScriptableObject 后，想确认没有搞坏引用。**

1. 在 Project 窗口中选中那个 ScriptableObject
2. 打开 Asset Reference Scanner
3. 点 **Scan Selected**
4. 如果 Issues 是 "OK"，说明没问题

### 深入理解：它怎么区分"真的空"和"丢失的引用"

Unity 的 SerializedObject 系统中，一个 ObjectReference 字段为 null 有两种情况：

1. **"真的空"**：`objectReferenceInstanceIDValue == 0` → 从来就没赋值过。不报错。
2. **"丢失的引用"**：`objectReferenceInstanceIDValue != 0` 但 `objectReferenceValue == null` → 曾经有引用，但目标文件被删了或 GUID 变了。这会被报告为 "Missing ref"。

对于 Prefab，它会递归遍历所有子物体和子组件，所以即使在深层嵌套的子物体上有丢失引用，也能被找出来。

另外，它特别检查了 `FurnitureDefinitionSO` 的 Sprite 字段——因为家具定义如果没有 Sprite 会直接导致家具不可见。

### 注意事项

- 只扫描 `Assets/_Project/` 下的资源。第三方插件、Unity 内置资源不在扫描范围内。
- 扫描结果不会自动刷新。修复问题后需要重新点 Scan。
- "Scan All" 在项目资源很多时可能较慢，建议在需要时定期使用，不要频繁操作。

## 6. Furniture Interaction Preview（家具交互预览编辑器）

### 它是干什么的

任何挂有 `Furniture` 组件的 GameObject，在 Inspector 中原本只显示 Furniture 脚本的默认字段（Id、Sprite 等）。这个自定义编辑器（CustomEditor）扩展了 Inspector 面板，让你看到更多调试信息：

- Definition（家具定义 SO）的完整性
- 交互类型、类别、持续时长、占用的格子
- 环境 Buff 效果（心情/精力增减）
- 场景绑定状态
- 与 `SceneFurnitureDefinitionHint` 的一致性检查
- 关键组件的健康状况

### 打开方式

这个工具**没有菜单入口**。它的使用方式是：

1. 在 Hierarchy 中选中一个挂有 `Furniture` 组件的 GameObject
2. 看 Inspector 面板 — `Furniture` 组件的显示已经被自定义编辑器接管了
3. 默认的字段显示完之后，下面多出来 "Interaction Preview" 区域

### 界面说明

在 Inspector 中，`Furniture` 组件的下方会新增以下区域：

**1. Definition 信息**

- `ID`：家具定义 SO 的 Id
- `Sprite`：是否已分配 Sprite（如果 MISSING，会有黄色警告）

**2. Interaction 信息**

- `Category`：家具类别（如 Seat / Bed / Decoration 等）
- `Type`：交互类型，用绿色显示；如果是 Unknown，用黄色警告
- `Duration`：交互持续时长（秒）
- `Placement`：放置类型
- `Occupied Cells`：占用格子数

**3. Environmental Buff 信息**

- 如果该家具有环境 Buff 效果：
  - `Mood: +X.X/s`（绿色）或 `-X.X/s`（红色）
  - `Energy: +X.X/s`（绿色）或 `-X.X/s`（红色）
- 如果没有 Buff："(No environmental buff)"

**4. Scene Binding 信息**

- `Is Scene Furniture`：是否为场景固定家具（true/false）
- `Sorting Order`：当前排序层级
- `SceneFurnitureDefinitionHint`：
  - 绿色 "Present" — 已挂载 Hint 组件
  - 黄色 "MISSING" — 没有挂载 Hint 组件
- 显示 Hint 中的 DefinitionId、Category、InteractionType
- 如果 Hint 的配置和 Definition 不一致，会有黄色警告提示：
  - `[WARNING] Hint DefId 'xxx' != Definition Id 'yyy'`
  - `[WARNING] Hint Interaction 'xxx' != Definition 'yyy'`
- `InteractionAnchor`：交互锚点是否存在、是否可用

**5. Components 健康检查**

- `SpriteRenderer`：Present / MISSING，如果有 SR 但没指定 Sprite 会警告
- `SortingGroup`：Present / None
- `Collider2D`：Present / None

**6. 快捷操作按钮**

- **Ping Definition**：在 Project 窗口中定位到该家具的 `FurnitureDefinitionSO`
- **Select Hint**：定位到该 GameObject 上的 `SceneFurnitureDefinitionHint` 组件

### 使用场景举例

**场景 1：摆了一件家具，但在游戏中交互不了。**

1. 在 Hierarchy 中选中该家具
2. 看 Inspector → Furniture → Interaction Preview
3. 检查：
   - Interaction Type 是不是 Unknown？→ 去 FurnitureDefinitionSO 中设置
   - InteractionAnchor 是不是 MISSING？→ 添加交互锚点
   - Hint 是不是 MISSING？→ 添加 SceneFurnitureDefinitionHint 并配置
   - 有黄色警告说 Hint 和 Definition 不一致？→ 修复 Hint 配置

**场景 2：想知道一件家具的环境 Buff 效果数值。**

1. 选中家具
2. 看 Inspector → Furniture → Environmental Buff 区域
3. 直接看到 Mood 和 Energy 的每秒变化量，不用去翻 FurnitureDefinitionSO 的 Buff 字段

**场景 3：新家具看不到，怀疑 Sprite 没设。**

1. 选中家具
2. 看 Inspector → Furniture → Components 区域
3. 检查 SpriteRenderer 和 Sprite 的警告信息
4. 同时看 → Definition → Sprite 是否存在

### 注意事项

- 这个编辑器是**只读**的。它用于调试和查看，不修改任何数据。修改数据请去对应的 ScriptableObject 或组件。
- 它只接管 `Furniture` 组件的 Inspector 显示。GameObject 上的其他组件不受影响。
- Hint 和 Definition 不一致的警告很重要——如果 Hint 的 DefinitionId 指错了，家具交互系统会用错误的配置，导致交互异常。

## 7. Pet Patrol Path（宠物巡逻路径）

### 它是干什么的

让你的桌宠沿指定路径移动。你可以在场景中放置一个 GameObject，挂上 `PetPatrolPath` 组件，然后在 Scene View 中可视化地编辑路径点（waypoint）。宠物会按路径点顺序移动，支持循环。

这个系统由两部分组成：
- `PetPatrolPath.cs` — 运行时代码，挂到 GameObject 上
- `PetPatrolPathEditor.cs` — 编辑器扩展，让你在 Scene View 和 Inspector 中编辑路径

### 第一步：创建 Patrol Path 对象

1. 在 Hierarchy 中右键 → **Create Empty**
2. 命名为 `PetPatrolPath`（或你喜欢的名字）
3. 在 Inspector 中点 **Add Component**，搜索 `Pet Patrol Path`，添加
4. 你会看到组件的 Inspector 显示：
   - **Loop** 勾选框：是否循环（走完最后一个点后回到第一个）
   - **Wait Time At Waypoint**：在每个路径点停留的秒数
   - **Gizmo Color**：Scene View 中路径线的颜色
   - **Gizmo Radius**：路径点球的大小
   - **Waypoints (0)**：路径点列表（目前为空）
   - 一个信息框，告诉你 Scene View 的快捷键操作

### 第二步：在 Scene View 中添加路径点

1. 在 Hierarchy 中**选中** `PetPatrolPath` GameObject（必须选中，否则 Scene View 不显示编辑界面）
2. 切换到 Scene View（如果你习惯 2D 视角，建议切到 2D 模式）
3. **按住 Shift 键，然后在场景中点击鼠标左键**

每点击一次，就会在该位置创建一个路径点。路径点以绿色小球显示，之间用绿色线段连接。

如果你想用 Inspector 添加：
- 在 Inspector 中点击 Waypoints 列表下方的 **+** 按钮，会在 `(0, 0)` 位置（即 GameObject 所在位置）添加一个路径点
- 然后你可以手动修改路径点的 X、Y 坐标

### 第三步：编辑路径点

**在 Scene View 中：**

- **选中路径点**：直接点击绿色小球，选中的会变成黄色
- **移动路径点**：选中后会出现一个位置操作手柄（类似移动工具的箭头），拖动手柄即可移动。所有修改都会被 Undo 系统记录，可以 Ctrl+Z 撤销。
- **添加路径点**：Shift + 左键点击空白位置，新增的路径点会自动被选中
- **删除路径点**：选中后按键盘上的 **Delete** 或 **Backspace** 键
- **取消选中**：按 **Escape** 键

**在 Inspector 中：**

- Waypoints 列表里每个路径点都显示编号、坐标，对应一个红色的 **X** 删除按钮
- 当前选中的路径点（通过 Scene View 点击选中）会在 Inspector 中以黄色高亮显示
- 点击 **Clear** 按钮可以清空所有路径点（有确认对话框）

### 第四步：配置路径参数

- **Loop**：勾选后，路径会首尾相连（最后一个点连回第一个）。Scene View 中会多一条线连接首尾。宠物走完最后一个点后会回到第一个。
- **Wait Time At Waypoint**：宠物到达每个路径点后暂停的秒数，默认 2 秒。设 0 就不停。
- **Gizmo Color / Gizmo Radius**：只影响编辑时的显示，不影响运行行为。

### 使用场景举例

**场景 1：让宠物在桌子上从左走到右再走回来。**

1. 创建一个 PetPatrolPath GameObject
2. 取消勾选 Loop（走到底就停，来回用两个路径对象控制）
3. 在 Scene View 中 Shift+左键，在桌子左边放一个点，右边放一个点
4. 如果想让它来回走：创建第二个 PetPatrolPath，路径点反过来排列
5. 在宠物移动脚本中引用这两个 Path 对象

**场景 2：让宠物沿房间绕圈巡逻。**

1. 创建一个 PetPatrolPath GameObject
2. 勾选 Loop
3. 在 Scene View 中沿房间墙壁依次 Shift+左键放置路径点
4. 设置 Wait Time At Waypoint = 3（每个角落停 3 秒）
5. 在宠物移动脚本中引用这个 Path，宠物就会一直循环巡逻

### 注意事项

- 路径点的坐标是**相对于 PetPatrolPath GameObject 的位置**，不是世界坐标。如果你移动 PetPatrolPath 对象，所有路径点会跟着一起移动。这样重新布局场景时不会搞乱路径。
- `GetWorldWaypoint(int index)` 方法返回的是世界坐标，供宠物移动脚本调用。你不需要手动计算。
- 在 Scene View 编辑时一定要注意工具栏状态——如果你当前选中了 Move/Rotate/Scale 工具，添加路径点还是可以的，但拖动手柄时可能会有意料之外的行为。建议使用 Move 工具（快捷键 W）。
- 如果你想看到路径点的序号，可以在 `OnDrawGizmos` 里加上 `Handles.Label`，但目前的版本没有加（避免运行时 asmdef 引用 UnityEditor）。

## 8. 用工具解决项目问题清单（逐一对照）

以下内容直接对应 Excel 修改清单中「程序」列和部分「美术」列的任务。每条都是 **问题描述 → 用什么工具 → 具体操作步骤**。


### 8.1 游戏封面 —「将两个控件改成中文」

**涉及文件**：开始封面上的按钮文本（如英文 Start / Load / Settings）。

**使用的工具**：UI Panel Diagnostic、Asset Reference Scanner

**步骤**：

1. 打开包含游戏封面的场景（通常是 Start 或 MainMenu 场景）
2. 打开 **UI Panel Diagnostic**，点 **Scan Scene**
3. 在列表中找出封面面板，确认它注册了 IUIPanel、Canvas 正常、没有丢失字体
4. 如果某行显示 "TMP 'xxx' has no font"——这就是按钮文字可能显示不出来的原因。点击该行定位到对应 TMP 对象，在 Inspector 中给它的 Font Asset 指定中文字体（如 `LXGWWenKai SDF`）
5. 打开 **Asset Reference Scanner**，点 **Scan All SO & Prefab**，确认所有字体 asset 的引用没有丢失
6. 回到 Unity 编辑器，直接在 Hierarchy 中找到按钮的 TMP_Text 组件，把文字从英文改成中文


### 8.2 存档界面 —「UI 替换」

**涉及文件**：存档/读档面板的整体 UI 资源。

**使用的工具**：UI Panel Diagnostic、Asset Reference Scanner

**步骤**：

1. 打开存档界面所在的场景
2. 打开 **UI Panel Diagnostic**，点 **Scan Scene**
3. 找到存档面板（名称可能包含 Save/Load 关键字），检查：
   - PanelId 是否已注册（不是 "Not Registered"）
   - 有没有 Image 缺少 Sprite（新 UI 替换后引用容易断）
   - TMP 字体是否正常
4. 打开 **Asset Reference Scanner**，选中新替换的 UI Prefab，点 **Scan Selected**，确保新资源没有 Missing ref
5. 如果有任何 "Missing ref" 报告，记下路径，去对应的 asset/prefab 中修复引用


### 8.3 侧边控件 —「添加手机那块 UI」「profile 改成中文」「提供每个按键选中的状态」

**涉及文件**：侧边栏/Hub UI 面板，包含手机入口按钮和 profile 信息。

**使用的工具**：UI Panel Diagnostic、Asset Reference Scanner

**步骤**：

**A. 添加手机 UI 区域：**

1. 在场景中创建手机入口的 UI 结构后
2. 打开 **UI Panel Diagnostic**，点 **Scan Scene**
3. 确认新加的 UI 面板出现在列表中，且 Canvas / GraphicRaycaster / PanelId 都是正常的
4. 如果有 "No GraphicRaycaster"——加一个 GraphicRaycaster 组件才能点击

**B. profile 改成中文 + 每项按键选中状态：**

1. 选中 profile 面板中的文本和按钮
2. 使用 **Asset Reference Scanner** 的 **Scan Selected** 扫描 profile 相关 Prefab
3. 确认按钮选中状态的 Sprite 引用没有丢失（Pressed / Highlighted / Selected 状态）
4. 在 Inspector 中给每个 Button 组件的 Transition 设置好对应的 Sprite State
5. 文本改中文直接在 Inspector 中修改 TMP_Text 的 text 字段


### 8.4 货币显示 —「每个界面那里都显示一下数额」

**涉及文件**：profile、公寓、抽签等界面的货币数量显示。

**使用的工具**：UI Panel Diagnostic、Debug Display Manager

**步骤**：

1. **首先关闭调试显示避免干扰**：打开 **Debug Display Manager**，如果有调试用的假数据文本在刷屏，勾掉对应开关（通常是 Chat Preview 和 Tarot Preview）
2. 打开目标场景
3. 打开 **UI Panel Diagnostic**，点 **Scan Scene**
4. 查找所有涉及货币显示的面板（profile / 公寓 / 抽签）
5. 检查每个面板是否有 "TMP 'xxx' has no font" 问题——货币数字如果字体缺失会显示为方块
6. 在运行时（Play Mode）验证货币数值是否正确更新：如果数值不显示，检查对应的 TMP_Text 绑定逻辑

### 8.12 收藏系统 —「展示物品大一点」

**使用的工具**：UI Panel Diagnostic、Asset Reference Scanner

**步骤**：

1. 打开收藏系统场景
2. **UI Panel Diagnostic** → **Scan Scene** → 找到收藏面板
3. 确认展示物品的 Image 组件的 Sprite 引用没有缺失
4. **Asset Reference Scanner** → **Scan Selected**（选中收藏系统相关 Prefab）→ 确认没有 Missing ref
5. 在 Hierarchy 中选中展示物品的 Image，在 Inspector 中调整 RectTransform 的 Width/Height 或 Scale 来放大

### 8.13 空间系统（美术）—「提交墙体/门的素材」「调整色调」

**使用的工具**：Furniture Label Validator、Asset Reference Scanner

虽然这是美术任务，但程序侧需要在素材提交后确保配置正确。

**步骤**：

1. 美术提交墙体和门的新 Sprite 后，导入 Unity
2. 打开 **Furniture Label Validator**，点 **Scan**
3. 检查所有墙体/门相关的家具——如果新的 Sprite 引用丢失，会在 "No Sprite assigned" 中暴露
4. 打开 **Asset Reference Scanner**，点 **Scan All SO & Prefab**，确认所有 `FurnitureDefinitionSO` 的 Sprite 引用完整
5. 色调调整在材质/Shader 层面处理——不属于这些工具的范围，但你可以通过 Furniture Interaction Preview 中的 Sprite 状态确认素材是否正常显示


### 8.14 开始抽签（美术）—「调整色调」+ 解牌（美术）—「调整色调」+ 图鉴（美术）—「调色」

这些都是色调调整任务。工具不能直接改色调，但可以帮你确保调整过程中不会搞坏现有的 UI 配置。

**步骤**：

1. **调色前**：打开 **UI Panel Diagnostic**，记录下当前有多少 Issue，作为基线
2. 对 UI 面板进行色调调整（修改 Image Color、Material 等）
3. **调色后**：再次点 **Scan Scene**，确认 Issue 数量没有增加——调色操作不应该引入新的 Missing Sprite 或 Canvas 问题
4. 用 **Asset Reference Scanner** 确认没有因为材质更换导致引用丢失
