# Gemini-Lab 上下文压缩与知识沉淀计划

Updated: 2026-05-12

## 这份文档的定位
这份文档用于记录 Gemini-Lab 第二部分工作方式升级的规划内容，包含：
- 渐进式上下文压缩
- 做梦整理
- L2 技能手册 / L3 知识库

它回答的不是“当前已经自动化到什么程度”，而是：
- 哪些能力已经纳入设计
- 哪些当前默认启用
- 哪些当前先只写入项目、暂不启用

## 当前结论总览

### 已纳入设计，但当前默认不启用
- 渐进式上下文压缩

### 已纳入设计，当前可采用人工版
- 做梦整理
- L2 技能手册
- L3 知识库

## 1. 渐进式上下文压缩

### 当前判断
这项能力对 Gemini-Lab 有价值，但**当前不是第一优先级**，因此：
- 已写入项目工作流设计
- 当前默认不启用自动压缩
- 当前只保留人工分层，不做自动压缩机制

### 为什么暂不启用
1. 当前主要痛点是任务边界失控，不是 Token 已经严重不足。
2. 过早压缩会带来细节损失，反而可能加重误判。
3. 现阶段先把 `L1 / L2 / L3` 的结构稳定下来更重要。

### 当前替代方式
- `L1`：当前任务保留细节
- `L2`：常驻记忆保留稳定规则和摘要
- `L3`：完整历史只做搜索，不默认加载

### 未来启用条件
当出现以下情况时，再考虑正式启用：
- 长会话频繁超过当前可稳定管理范围
- 同一主题跨很多轮反复回溯
- `L2` 文档体量明显难以维护

## 2. 做梦整理

### 当前判断
这部分值得开始建设，但当前先采用：
- **定期人工整理**
- **半自动提示**

不做：
- 后台自动重写记忆
- 自动删除旧内容

### 当前推荐做法
每隔一段时间，人工做一轮整理：
1. 检查 `docs/current-task-card.md` 是否已过期
2. 检查 `docs/ai-memory/gemini-lab-memory-main.md` 是否有重复表述
3. 检查 `docs/ai-memory/gemini-lab-memory-rules-and-history.md` 是否有过长流水记录
4. 检查 `memory-index.paths.txt` 是否仍对得上现有文件
5. 检查 skill 清单与 skill 目录是否一致

### 当前目标
让记忆：
- 去重
- 保持入口清晰
- 不把旧阶段细节继续堆进主记忆

## 3. L2 技能手册

### 当前判断
这部分已经可以开始建设。

### 什么内容应该进 L2 技能手册
满足以下任一条件的流程，优先沉淀：
1. 已经重复做过 3 次以上
2. 风险较高
3. 容易因为命令链过长而出错
4. 需要固定输入 / 固定顺序 / 固定验证方式

### 当前已开始沉淀的内容
当前已经落地为 workflow skill 的可视作第一批技能手册：
- `git-sync-upstream-main`
- `unity-clear-generated-cache`
- `apartment-scene-rollback-to-commit`
- `pet-animation-reference-rebuild`
- `furniture-binding-check`

### 后续可以继续沉淀的方向
- Prefab 替换流程
- 家具场景绑定修复流程
- Pet 动画资源命名收口流程
- GitHub PR 冲突处理流程

## 4. L3 知识库

### 当前判断
这部分适合先做“轻索引”，不做复杂系统。

### 当前来源
- git 历史
- PR 历史
- 长文档
- 旧阶段说明

### 当前目标
不是建设完整向量知识库，而是先明确：
- 哪些属于长期档案
- 这些档案默认不加载
- 真需要时通过搜索或索引再取

### 当前推荐做法
- 继续维护 `docs/ai-memory/memory-index.paths.txt`
- 在主记忆里只保留“入口”和“摘要”
- 更详细的历史留在原文档、git 和 PR 里

## 5. 当前优先级结论

### 立即启用
- 做梦整理（人工版）
- L2 技能手册（逐步沉淀）
- L3 知识库（索引版）

### 暂不启用
- 渐进式上下文压缩的自动化执行

## 6. 下一步建议
1. 先把“做梦整理”的检查清单单独落成文档。
2. 继续按“重复 3 次以上”原则补 workflow skill。
3. 等第一批 skill 稳定后，再判断是否真的需要自动压缩。
