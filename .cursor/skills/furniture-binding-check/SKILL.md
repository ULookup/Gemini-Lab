# Furniture Binding Check

## 适用场景
当用户明确要求：
- “检查家具绑定”
- “看看 ApartmentSceneFurnitureBindings 还有没有漏项”
- “检查场景里的家具对象是否都正确接进交互链”

并且目标是：
- 先做只读核查
- 优先检查 Apartment 场景里的家具绑定链
- 明确区分“脚本已支持”“场景已绑定”“目标引用已失效”三种情况

这个 skill 就应该使用。

## 目标
安全完成以下结果：
1. 盘点当前场景里的家具绑定状态。
2. 识别重复绑定、空 `_target`、漏接对象、类别/定义 ID 错误等问题。
3. 明确哪些是脚本问题，哪些是场景配置问题，哪些只是资源还没接进场景。
4. 默认只做检查，不自动修改。

## 前置规则
1. 必须先遵守 `AGENTS.md`：
   - 先复述理解
   - 用户明确说“执行”后再操作
2. 默认这是只读检查 skill，不自动进入修复。
3. 必须先确认目标范围：
   - 默认以 `Assets/_Project/Scenes/Apartment/Apartment_Main.unity`
   - 以及 `Assets/_Project/Scripts/Modules/Furniture/**`
   为核心
4. 如果后续要修复，必须单独得到用户确认。

## 标准流程

### Step 1. 只读盘点
优先检查：
- `Apartment_Main.unity`
- `ApartmentSceneFurnitureBindings.cs`
- `FurnitureService.cs`
- `SceneFurnitureDefinitionHint.cs`
- 覆盖清单文档（如果存在）

目标：
- 分清当前绑定是“场景序列化绑定”还是“运行时自动找回”

### Step 2. 问题分类
至少按以下类型归类：
- 重复绑定
- 空 `_target`
- 资源存在但未进场景
- 场景对象存在但未进绑定
- 定义 ID / 类别 / 交互类型不一致
- 脚本已支持但文档过期

### Step 3. 输出结果
优先给出：
- 哪些对象已经正确绑定
- 哪些对象明显漏了
- 哪些对象只是名字/定义写歪了
- 哪些对象不建议纳入交互链

### Step 4. 如需修复
只有在用户明确要求后，才进入修复阶段。
修复时应保持：
- 场景层与脚本层分开说明
- 不顺手扩大到无关家具或无关场景

## 不要做的事
- 不默认修改场景
- 不默认回退场景
- 不默认把所有家具都接成可交互
- 不顺手改 Pet 动画或 UI

## 成功判定
满足以下全部条件才算完成：
1. 当前家具绑定状态已被盘点清楚。
2. 问题已分类成可执行的下一步。
3. 检查结果明确区分了脚本层、场景层与资源层。
